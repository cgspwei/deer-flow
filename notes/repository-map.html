1. 项目定位

DeerFlow 2.0 — 基于 LangGraph 的 AI super-agent harness（全栈 monorepo）。单个 lead agent 编排 sub-agents、持久记忆、沙箱执行、可扩展 skills / tools，按 thread 隔离。v2 是彻底重写，与 v1（1.x 分支）无共享代码。

1.1 一句话定义：它不是「一个 Agent」，而是「跑 Agent 的运行环境」

README 的原话是："DeerFlow started as a Deep Research framework — and the community ran with it… That told us something important: DeerFlow wasn't just a research tool. It was a harness — a runtime that gives agents the infrastructure to actually get work done."

换个说法：「框架」要你自己接线；「harness」出厂即带电池。 DeerFlow 2.0 开箱即提供：

文件系统
Agent 能真实读写文件、留存产物（PPT / 图表 / 网页 / 视频脚本），而不是只在对话里「描述」结果。
沙箱执行
bash / 代码在隔离环境里跑（local / provisioner / K8s 模式），可开关 bash 与文件写权限。
长期记忆
跨 thread 记住用户事实与偏好，v1 Markdown 记忆可单向迁移到 v2。
Skills 扩展
23 个内置技能包 + 导入 .skill 归档 + MCP 服务器，能力可插拔。
Sub-agents
复杂多步任务自动规划并派发子 agent（bash_agent / general_purpose / 自定义），支持 isolated 与 snapshot 两种上下文模式。
四种 UI 入口
Web 工作台、终端 TUI、IM 通道（飞书/Slack/Telegram…）、内嵌 Python 客户端。

所以你可以 直接用，也可以 拆开改造成自己的 Agent 产品 —— 这是它和「一个 Deep Research Demo」最本质的区别。

2.4 按「使用姿势」归纳的 6 类场景

A · 个人超级助理（Web / TUI）
在聊天框里下复杂任务，它自己规划、检索、跑代码、交付文件。
路径 /workspace/chats/[thread_id] 或 deerflow CLI；TUI 与 Web 共享 thread store，两边同步。
B · 定时自动化流水线
把「每周竞品追踪」「每日舆情摘要」配成 Scheduled Task，可选择复用 thread（带历史上下文）或每次新建。
路径 /workspace/scheduled-tasks + app/scheduler/。
C · 团队知识/项目空间
用 Projects 承载团队约定：项目级 instructions 会在每次 run 时渲染成请求级 <project> 块注入（不进系统提示、不进历史），成员 thread 自动继承。
上限 默认 8192 字节（可配 256–262144）。
D · 嵌入 IM 工作流的机器人
接到飞书 / Slack / Telegram / Discord / 企微 / 钉钉 / WeChat / Buzz / GitHub Webhook，在群里被 @ 就开干。
路径 backend/app/channels/*；Lark 插件还能连文档、日历、多维表格。
E · 嵌入自有系统的 Agent 内核
用 DeerFlowClient 在 Python 进程内直接调用，返回与 HTTP Gateway 相同的 schema，不启服务也能用；或用 create_deerflow_agent() 直接拿 LangGraph 图。
典型 后端批处理、离线任务、二次开发产品。
F · 作为 Agent 产品的底座（二次开发）
写自定义 skill / MCP 插件 / sub-agent / 中间件，把它变成垂直领域 Agent（法律、医疗、运维、投研…）。
路径 deerflow/extensions/ + deerflow_extension_api（契约 pin ==0.2.1）。

2.5 一个端到端例子（把上面的零件串起来）

需求：「帮我做一份 2026 Agent 趋势报告，做成网页并部署上线」 1. 用户在 Web 聊天框发一句自然语言需求 2. Lead Agent 规划 → 派发 sub-agent 并行检索（isolated 上下文，互不污染） 3. 检索结果汇总 → 调用 deep-research 类流程产出报告 4. 在沙箱里生成 HTML 页面（真实文件，可下载） 5. 调 vercel-deploy-claimable → 拿到预览 URL 与可认领链接 6. 全流程 SSE 流式回传：工具卡片、进度、产物 7. Thread 持久化 → 可在 /showcase 只读回放分享（落地页 case study 就是这么来的） → 想每周自动跑一遍？把它存成 Scheduled Task → 想在飞书群里触发？接上 Lark 通道 → 想每天定时把结果推群？加 WeCom 群机器人插件
选型判断：什么时候适合用 DeerFlow
适合：需要「能真干活」的 Agent —— 要联网、要跑代码、要产出文件、要多步编排、要长期记忆、要接进现有渠道。
不适合：只想做单轮问答/简单 RAG 聊天机器人（杀鸡用牛刀）；或完全不能接受 Agent 执行代码/写文件的环境（虽可关闭 bash 与写权限，但那就浪费了它的核心卖点）。
安全提示（README 明确警告）
部署不当会引入安全风险：Agent 具备 bash 与文件写能力。请按需关闭 bash / 文件写工具、启用沙箱模式，并遵循 README 的 Security Recommendations。
